## 見つけて修正した不具合

0.1.1は撮影命令の開始時にLIGHTかどうかを確認していましたが、予測・待機中に
DARKへ変更すると、撮影開始の直前に確認し直さず、その設定で撮影処理へ進みました。
撮影要求を止める模擬カメラを使ったテストで、修正前に問題を再現しました。

0.1.2は、待機を終えた直後にLIGHT限定やNINA標準の前提条件を再確認します。
待機中に予測エンジンの場所が変わった場合も、撮影せず再実行を求めます。
実際のカメラ・赤道儀・屋根への操作は行っていません。

## 撮影命令を実行した追加テスト

NINA 3.2の実際のSDKを使い、予測の応答とカメラ・保存・履歴の窓口を模擬化しました。
通常の撮影処理への到達は確認しますが、実画像の処理・保存の成功はここでは確認しません。

| 条件 | 確認した結果 |
|---|---|
| 古いデータを表す予測エラー | 撮影・保存・履歴への呼び出しなし |
| 応答形式の予測エラー | 同上 |
| エンジン利用不能の予測エラー | 同上 |
| 露光枠がない | 待機期限で停止、撮影なし |
| 計算中の中止 | 中止を返し、撮影なし |
| 待機中にDARKへ変更 | 撮影なし |
| 待機中にFLATへ変更 | 撮影なし |
| 待機中にエンジン指定を変更 | 再実行を求めて停止、撮影なし |
| 計算中に対象の赤経を変更 | 新しい対象で再計算した後だけ撮影処理へ進む |
| 中止した同じ命令を再実行 | 次の実行で通常の撮影処理へ進める |
| 条件を満たす露光枠 | NINA標準の撮影窓口へ露光時間・ゲイン・オフセット・ビニングを1回渡す |
| NINA標準形式で保存・読み込み | プラグインの型・設定値・親シーケンスへの参照が復元される |
