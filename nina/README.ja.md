# N.I.N.A.用 dodge satelite（実験版）

[English](README.md) · [検証記録](VALIDATION.md)

コードを読まずに始める場合は、[画面での確認手順](TRY_IT.ja.md)から進めてください。

現行安定版 **N.I.N.A. 3.2.0.9001 / Windows x64** の高度なシーケンサーに、
**dodge satelite: Satellite-aware Exposure** を追加します。衛星の予測通過区間を避けて待機し、
NINA標準の処理でLIGHTフレームを1枚撮影・保存します。繰り返し撮影には通常のループを使います。
対象・観測地・機材情報はNINAから取得します。予測エンジンを同梱し、Pythonや別アプリの起動は不要です。

**実写精度は未検証で、写り込みを保証する機能ではありません。** データにない衛星、古い軌道、
サンプル間の変化、追尾・露光開始の遅延により見逃しがあり得ます。NINA 3.3/nightlyやARM64は未検証です。

## 導入

0.2.0ではDLL名と命令内部の型名も新しくしました。NINAを閉じて以前のプラグインを
取り除いてから、新版を展開してください。古いDLLと新しいDLLを混在させないでください。
プラグイン識別子は維持していますが、以前保存したシーケンスは変換が必要な場合があります。
次のコマンドは、デスクトップ版CLIまたはソース版を導入した環境で使います。
実行ファイル版を現在のフォルダーから使う場合は先頭を `.\dodge-satelite.exe` にしてください。

```powershell
dodge-satelite migrate-nina previous.json --out updated.json --bundled-engine
```

元ファイルを上書きせず、新しいJSONファイルを作ります。内容のコード実行は行いません。
`.NINA.SatelliteAwareExposure` で終わる命令の型参照だけを変更します。任意の
`--bundled-engine` はエンジンの上書きパスを空欄に戻し、新しい同梱版を使う指定です。
変換後はNINAで開いて設定を確認してください。画面で命令を削除・追加し直す方法も使えます。

1. [プラグイン用Release](https://github.com/Aoi-Morio/dodge-satelite/releases/tag/nina-v0.2.0) から
   `Dodge-Satelite-NINA-0.2.0-windows-x64.zip` を取得します。
2. 撮影中ではないことを確認してNINAを終了します。
3. `%LOCALAPPDATA%\NINA\Plugins\3.0.0\` を開き、`dodge satelite` フォルダーを作成します。
   `3.0.0` はNINA 3.2が使うプラグイン互換フォルダーの名前です。
4. ZIPの**中身**をそこに展開します。DLL 2個と `Engine` フォルダーを同じ階層に置きます。
   ZIP名のフォルダーが余分に入らないようにし、エンジンとライセンス資料を含む全ファイルを残してください。
5. NINAを起動し、高度なシーケンサーの **dodge satelite** カテゴリーから命令を追加します。

現時点では**手動導入版**です。NINA公式の一覧にはまだ掲載されていません。
公式Beta枠への[申請資料](REGISTRY_SUBMISSION.md)を用意しています。申請前に作者自身によるレビューとテストが必要です。
登録用マニフェストは提供しますが、審査・登録済みという意味ではありません。
削除はNINAを閉じてこのプラグインのフォルダーだけを除去します。他の設定やプラグインは変更不要です。

## 撮影

- Deep Sky Objectのシーケンス内に命令を置きます。露光時間・ゲイン・オフセット・ビニングはNINAの通常の欄で設定します。
  DARK/FLAT等の校正フレームや非恒星時追尾には使いません。
- NINAの観測地、焦点距離、未ビニングのピクセルサイズを正しく設定し、撮影用カメラを接続します。
  センサーの幅・高さは画素数とピクセルサイズから算出します。必要なら詳細設定でmm値を上書きできます。
- 既定の衛星群は **visual** です。**一部の衛星しか含まれません。Starlink全体や全衛星を覆うものではありません。**
  `starlink` や `active` も選べますが、どの群でも未登録衛星は対象外です。
- 初回にCelesTrakから取得し、以後は2時間の再取得制限を守ります。「オフライン」は既存キャッシュだけを使います。
  観測地・対象・画像は送信せず、通信するのは衛星群の取得要求のみです。
- 元期差の上限（既定2日、設定上限7日）、取得から24時間、計算失敗などを検出すると、その露光は開始しません。
  1件でも古い要素があると停止するため、大きなカタログでは群や閾値の選定が必要です。古い衛星を黙って除外しません。
- 枠がなければ既定で最大10分待機し、その後エラーにします。NINAのエラー処理は既定で **Abort on Error** です。
  利用者がNINAのエラー処理を変更した場合、後続命令は継続する場合がありますが、この命令では露光しません。
- 中止操作は待機と予測プロセスへ伝わります。開始済みの露光はNINA標準の中止処理に従います。

予測結果は最大2分、対象・場所・機材・露光・判定条件が同一のときだけ再利用します。
露光開始前にもう一度条件を確認し、露光全体と開始遅延の余裕が予測枠に収まる場合に撮影します。

既定は予測5分・サンプル1秒・角度余裕0.1°・通過前後3秒・露光開始の余裕3秒です。
**これらは実測で校正した誤差範囲ではありません。** カメラの開始遅延が余裕を超える場合などは回避できません。
通過に合わせて撮影中のフレームを自動中断する仕組みではありません。NINAの安全監視、天候管理、
子午線反転の代わりには使わないでください。待機によってシーケンスが延びる点も考慮してください。

## 開発・検証

ビルドとテストは [English README](README.md) を参照してください。
NINA SDKを実際に参照したMEF構成、XAMLリソースの読み込み、複製、ゲートの時刻・データ検証、
中止・タイムアウト、Pythonとの入出力を検証します。実機カメラや実写での精度は別途検証が必要です。
